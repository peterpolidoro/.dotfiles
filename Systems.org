* Systems

** Upgrading

The live workstation still uses Debian plus Stow and the =desktop= / =emacs=
extra Guix profiles.  Guix Home has been tested separately, but has not taken
ownership of this home yet.  These commands are the transition interface:

| Command | Scope |
|---------+-------|
| =upgrade-workstation --dry-run= | Preview the routine update without changing packages |
| =upgrade-workstation= | Debian (or Guix System), user Guix pins, default profile if present, installed extra profiles |
| =upgrade-guix-user= | Apply user channel pins and rebuild user profiles; no OS/root update |
| =upgrade-guix-user emacs= | Apply user channel pins, then rebuild only the Emacs extra profile |
| =upgrade-profiles emacs= | Rebuild only Emacs using the already-selected user Guix |
| =activate-profiles desktop emacs= | Install exactly the named profiles |
| =upgrade-system= | Debian packages, or Guix System reconfiguration |
| =upgrade-guix-root= | Root's Guix and AppArmor policies on Debian; separate manual maintenance |
| =upgrade-workstation --root-guix= | Include root Guix maintenance in this run |
| =upgrade-guix= | Compatibility command preserving the old OS + root + user update |
| =upgrade-all= | The legacy broader update, then repository pulls and mail synchronization |
| =upgrade-dotfiles= | Retangle the Org sources and refresh Stow links |

All of these commands accept =--dry-run=.  The preview prints commands and
validates inputs; it does not call apt, sudo, Guix, Stow, repository pulls, or
mail synchronization.  APT uses the same full-upgrade / autoremove policy as
the old script.  A failed step stops later steps; earlier successful steps
are not rolled back automatically.

Use =upgrade-workstation= for the regular update.  Keep root Guix maintenance
manual and less frequent (the migration plan proposes monthly).  Root has its
own channels and daemon lifecycle; the canonical user pin set does not replace
root's channel configuration.  =upgrade-all= remains an explicit broad action
because it also modifies repository checkouts and synchronizes mail.

*** Applying pins versus choosing newer versions

User channels are pinned to exact commits.  =guix pull= now applies that pin set;
it does not advance those commits to current branch tips.  User update scripts
pass the live channel file explicitly and prefer the user's current Guix over
an executable inherited from a project shell.  After pulling, profile rebuilds
use the newly selected user Guix.  No profiles are sourced into these child
scripts; open a new login session when the login environment needs refreshing.

Before pulling, the helpers compare =~/.config/guix/channels.scm= with
=~/Repositories/codeberg/home-config/files/config/guix/channels.scm= when the
canonical checkout is present.  Drift stops the update before any package
changes.  The canonical file is maintained in =home-config=; =Desktop.org=
and its tangled channel file are the Stow-era mirror.  Edit the Org block too
when changing that mirror, so retangling cannot silently restore older pins.

For a new package set:

1. Choose and validate new commits in the canonical =home-config= pin file.
   Check substitutes for the heavy manifests before advancing Guix itself.
2. Update the mirror in =Desktop.org= and retangle the channel file.  Sync only
   the project channel subsets that are intended to adopt this change, using
   =guix-agent-tools-sync-channels= from its checkout until the installed
   package includes that helper.
3. Run =upgrade-workstation --dry-run=, then =upgrade-workstation=, or use
   =upgrade-guix-user emacs= for an Emacs-only profile rebuild after pulling.

Unpublished configuration edits are a separate input: the Emacs packages fetch
pinned source payload commits.  Publish the Emacs source changes, update the
package payload commit/hash and release version, then publish that package
recipe and update the canonical Emacs channel pin to that recipe commit.
Only then will a routine user update install those edits.  A channel pin and a
package's source pin are two distinct revisions.

On another machine joining an older shared pin set, an intentional one-time
pull may require =--allow-downgrades=.  The routine scripts do not add that
flag automatically:

#+begin_src sh
~/.config/guix/current/bin/guix pull --channels="$HOME/.config/guix/channels.scm" --allow-downgrades
upgrade-profiles
#+end_src

*** Migration boundary and validation

Keep these helpers in =.dotfiles= until the helper-file cutover to =home-config=.
At that cutover each path gets one owner: remove its Stow ownership as Guix Home
starts managing it.  Later the user-package step becomes =guix home reconfigure=
when packages migrate.  The separate OS command remains useful.  Repository
management stays a separate action while Orb Registry and Loom are adopted.

The planned weekly pin-selection/substitute-check/warm job belongs in
=home-config=.  The current helpers apply reviewed pins and do not schedule
updates, advance pins, switch home ownership, or collect Guix generations.

Run =make test= to exercise the orchestration against fake executables in
temporary directories.  The tests never perform a real upgrade.  The optional
=GUIX_UPDATE_GUIX=, =GUIX_UPDATE_CHANNELS=, =GUIX_UPDATE_CANONICAL_CHANNELS=,
=GUIX_UPDATE_PROFILE_ROOT=, =GUIX_UPDATE_MANIFEST_DIR=, and
=GUIX_UPDATE_DEFAULT_PROFILE= environment variables select alternate locations;
they also allow tests without changing =HOME=.  A bootstrap without an installed
user Guix falls back to =guix= on =PATH= for the first pull.

*** =.local/libexec/upgrade-common.sh=

#+begin_src sh :tangle .local/libexec/upgrade-common.sh :tangle-mode (identity #o444)
# Generated from Systems.org; sourced by the upgrade commands.
# Always resolve sibling commands through the real script, including Stow links.
UPGRADE_SCRIPT_DIR=$(dirname "$(readlink -f "$0")")
UPGRADE_DRY_RUN=0
UPGRADE_ROOT_GUIX=0
UPGRADE_NAMES=

upgrade_die() { printf '%s\n' "$*" >&2; exit 1; }

upgrade_parse()
{
    for upgrade_arg do
        case "$upgrade_arg" in
            --dry-run) UPGRADE_DRY_RUN=1 ;;
            --root-guix) UPGRADE_ROOT_GUIX=1 ;;
            -h|--help) upgrade_usage; exit 0 ;;
            ''|[!a-zA-Z0-9]*|*[!a-zA-Z0-9._-]*)
                upgrade_die "Invalid option or profile name: $upgrade_arg" ;;
            *) UPGRADE_NAMES="${UPGRADE_NAMES}${UPGRADE_NAMES:+ }$upgrade_arg" ;;
        esac
    done
}

upgrade_run()
{
    if [ "$UPGRADE_DRY_RUN" -eq 1 ]; then
        printf 'Would run:'
        for upgrade_arg do printf ' <%s>' "$upgrade_arg"; done
        printf '\n'
    else
        "$@"
    fi
}

upgrade_child()
{
    upgrade_command=$1
    shift
    if [ "$UPGRADE_DRY_RUN" -eq 1 ]; then
        "$UPGRADE_SCRIPT_DIR/$upgrade_command" --dry-run "$@"
    else
        "$UPGRADE_SCRIPT_DIR/$upgrade_command" "$@"
    fi
}

upgrade_no_profiles()
{
    [ -z "$UPGRADE_NAMES" ] || upgrade_die 'This command does not accept profile names.'
}

upgrade_no_root_option()
{
    [ "$UPGRADE_ROOT_GUIX" -eq 0 ] || upgrade_die 'Use upgrade-guix-root for root Guix maintenance.'
}

upgrade_select_guix()
{
    # A project shell can put a different, single-channel Guix first on PATH.
    UPGRADE_GUIX=${GUIX_UPDATE_GUIX:-${XDG_CONFIG_HOME:-$HOME/.config}/guix/current/bin/guix}
    if [ ! -x "$UPGRADE_GUIX" ]; then
        [ -z "${GUIX_UPDATE_GUIX:-}" ] || upgrade_die "Guix is not executable: $UPGRADE_GUIX"
        UPGRADE_GUIX=$(command -v guix) || upgrade_die 'No Guix executable found.'
        printf 'Bootstrapping user Guix with %s\n' "$UPGRADE_GUIX" >&2
    fi
}

upgrade_check_channels()
{
    UPGRADE_CHANNELS=${GUIX_UPDATE_CHANNELS:-${XDG_CONFIG_HOME:-$HOME/.config}/guix/channels.scm}
    UPGRADE_CANONICAL_CHANNELS=${GUIX_UPDATE_CANONICAL_CHANNELS:-$HOME/Repositories/codeberg/home-config/files/config/guix/channels.scm}
    [ -r "$UPGRADE_CHANNELS" ] || upgrade_die "Missing channel file: $UPGRADE_CHANNELS"
    if [ -f "$UPGRADE_CANONICAL_CHANNELS" ] &&
       ! cmp -s "$UPGRADE_CANONICAL_CHANNELS" "$UPGRADE_CHANNELS"; then
        upgrade_die "Channel files differ. Reconcile $UPGRADE_CHANNELS with $UPGRADE_CANONICAL_CHANNELS before updating. See Systems.org."
    fi
}

upgrade_prepare_profiles()
{
    UPGRADE_PROFILE_ROOT=${GUIX_UPDATE_PROFILE_ROOT:-$HOME/.guix-extra-profiles}
    UPGRADE_MANIFEST_DIR=${GUIX_UPDATE_MANIFEST_DIR:-${XDG_CONFIG_HOME:-$HOME/.config}/guix/manifests}
    # Names are validated by upgrade_parse, so this split cannot expand globs.
    if [ -z "$UPGRADE_NAMES" ]; then
        for upgrade_dir in "$UPGRADE_PROFILE_ROOT"/*; do
            [ -d "$upgrade_dir" ] || continue
            upgrade_name=${upgrade_dir##*/}
            case "$upgrade_name" in
                ''|[!a-zA-Z0-9]*|*[!a-zA-Z0-9._-]*)
                    upgrade_die "Invalid installed profile name: $upgrade_name" ;;
            esac
            UPGRADE_NAMES="${UPGRADE_NAMES}${UPGRADE_NAMES:+ }$upgrade_name"
        done
    fi
    # Validate the entire selection before changing the first profile.
    for upgrade_name in $UPGRADE_NAMES; do
        [ -r "$UPGRADE_MANIFEST_DIR/$upgrade_name.scm" ] ||
            upgrade_die "Missing manifest: $UPGRADE_MANIFEST_DIR/$upgrade_name.scm"
    done
}

upgrade_system_kind()
{
    if [ -n "${GUIX_UPDATE_SYSTEM_KIND:-}" ]; then
        UPGRADE_SYSTEM_KIND=$GUIX_UPDATE_SYSTEM_KIND
    elif [ -e /run/current-system ]; then
        UPGRADE_SYSTEM_KIND=guix
    elif [ -r /etc/debian_version ]; then
        UPGRADE_SYSTEM_KIND=debian
    else
        upgrade_die 'Unsupported host OS; this helper supports Debian and Guix System.'
    fi
    case "$UPGRADE_SYSTEM_KIND" in debian|guix) ;; *) upgrade_die 'Unsupported host OS.' ;; esac
}
#+end_src

        upgrade_run sudo apt clean -y
        upgrade_run sudo apt autoclean -y

sync_guix_apparmor_profiles()
{
    # guix pull updates root's profile, but it does not update the copies of
    # Guix's AppArmor policies under /etc.  Keep those copies and the loaded
    # policies in sync on foreign distributions that enable AppArmor.
    if [ ! -r /sys/module/apparmor/parameters/enabled ] ||
       ! grep -qx 'Y' /sys/module/apparmor/parameters/enabled; then
        return 0
    fi

    GUIX_APPARMOR_SOURCE=/var/guix/profiles/per-user/root/current-guix/etc/apparmor.d
    if [ ! -d "$GUIX_APPARMOR_SOURCE" ]; then
        echo "AppArmor is enabled, but root's Guix profile contains no AppArmor policies; skipping synchronization." >&2
        return 0
    fi

    if [ -x /usr/sbin/apparmor_parser ]; then
        GUIX_APPARMOR_PARSER=/usr/sbin/apparmor_parser
    elif [ -x /sbin/apparmor_parser ]; then
        GUIX_APPARMOR_PARSER=/sbin/apparmor_parser
    else
        echo "AppArmor is enabled, but apparmor_parser is unavailable." >&2
        return 1
    fi

    echo "Synchronizing Guix AppArmor policies..."
    upgrade_run sudo cp -f "$GUIX_APPARMOR_SOURCE/tunables/guix" /etc/apparmor.d/tunables/guix
    upgrade_run sudo cp -f "$GUIX_APPARMOR_SOURCE/guix-daemon" "$GUIX_APPARMOR_SOURCE/guix" /etc/apparmor.d/
    upgrade_run sudo "$GUIX_APPARMOR_PARSER" --warn=all -r /etc/apparmor.d/guix-daemon
    upgrade_run sudo "$GUIX_APPARMOR_PARSER" --warn=all -r /etc/apparmor.d/guix
}


# Root keeps its own Guix channels; this is separate from the user's pin set.
sync_guix_apparmor_profiles
upgrade_run sudo -i guix pull
sync_guix_apparmor_profiles
printf '%s\n' 'Root Guix update does not restart the daemon.' \
    'Restart guix-daemon from a clean TTY or after leaving the Guix-backed desktop.'
#+end_src

On a Debian-based foreign distro, do not restart =guix-daemon= automatically
from a live graphical session if the session is using Guix-backed binaries.
Those processes can keep =/gnu/store= busy, which prevents =gnu-store.mount=
from unmounting cleanly during daemon restart and leaves the daemon with a
read-only store view.

If AppArmor is enabled, the upgrade script copies the policies shipped by
root's current Guix profile to =/etc/apparmor.d= and reloads them both before
and after =guix pull=.  The first synchronization repairs stale installed
policies using the last successful pull; the second picks up policy changes
from the new pull.  Reloading an AppArmor policy does not require restarting
=guix-daemon=.

If you need to restart =guix-daemon= after updating root's Guix, do it from a
clean TTY or after logging out of the desktop session:

#+begin_src sh
sudo systemctl restart guix-daemon
sudo nsenter -t "$(pidof guix-daemon)" -m findmnt /gnu/store
#+end_src

The daemon's view of =/gnu/store= should be =rw=.

* Profile Management

I like to separate my packages into separate manifests that get installed as
profiles which can be upgraded independently. These profiles get installed under
the =~/.guix-extra-profiles= path and sourced by my =~/.profile= when I log in.

To make the management of multiple profiles easier, I've created a couple of shell scripts:

This script requires explicit manifest names (without extension) under =~/.config/guix/manifests= and installs only those profiles.  It uses the same rebuild helper as =upgrade-profiles=.  For example:

#+begin_src sh

#+end_src

#+begin_src emacs-lisp :tangle tangle-dotfiles.el

(require 'org)
;; Don't ask when evaluating code blocks
(setq org-confirm-babel-evaluate nil)

(let* ((dotfiles-path (expand-file-name "~/.dotfiles"))
	     (org-files (directory-files dotfiles-path nil "\\.org$")))

  (defun pjp/tangle-org-file (org-file)
    (message "\n\033[1;32mUpgrading %s\033[0m\n" org-file)
    (org-babel-tangle-file (expand-file-name org-file dotfiles-path)))

  ;; Tangle Systems.org first
  (pjp/tangle-org-file "Systems.org")

  (dolist (org-file org-files)
    (unless (member org-file '("README.org" "Systems.org"))
      (pjp/tangle-org-file org-file))))

#+end_src
